# 요구사항 — 홈페이지

몽키즈 홈페이지(웹 서비스)의 요구사항 단일 출처다. 프론트엔드와 백엔드가 공유한다.
다른 프로젝트의 요구사항은 같은 폴더의 `requirement_{프로젝트}.md`에 둔다 (예: [requirement_employee.md](requirement_employee.md)).
기능·화면에는 ID를 붙이고, 커밋·PR·각 영역 문서에서는 이 ID로 참조한다.

> **작성 방식**: 회의록(`docs/meetings/`)을 바탕으로 `/extract-requirements`를 실행해 갱신한다.
> 초안을 확인·승인한 뒤 반영하며, 각 항목의 `출처`에 근거 회의록을 적는다.
> 구현·설계 작업은 회의록이 아니라 이 문서를 기준으로 한다.

## 개요

방문 유아체육 전문 브랜드 **몽키즈**의 웹 서비스.

## 미결 사항

- SCR-002는 구성을 정했지만(디자인 초안 승인, 2026-10-20) 빈칸 문구(강사 교육 과정, 연령 구분·월별 커리큘럼, 테마·교구 예시, 대체강사 배정 방식, 안전 기준, 대표 관리 방식, 강사 정보·사진)는 대표 확인이 필요하다.
- SCR-022의 분류별 질문·답변은 기획 v4 FAQ 문구로 채웠다(2026-10-20). 운동회·체육대회와 복지센터·공공기관은 같은 질문 2개를 함께 쓴다. 문구의 사실 여부는 대표 확인이 필요하다. SCR-008 고객센터(MVP 제외)와 병합할지는 미정이다.
- 플로팅 메뉴(SCR-001) 추가 변경 여부. 전화 문의와 "후기 보러가기"는 유지하기로 했다 (출처: 2026-10-29).
- 후기 작성 코드 세부(ADR-005 후속 작업): 코드 종류별 사용 횟수·만료 기간 기본값, 코드에 후기 유형(무료체험/수업)을 묶을지, 링크로 열면 코드가 자동 입력되는지, 도입 전 후기 처리(그대로 / 확인 후 숨김 / 구분 표시), 후기 수정(FR-025) 때 코드 재확인 여부(기본안: 작성 시 1회만) (출처: 사용자 결정(2026-10-29, [ADR-005](../adr/ADR-005-review-author-eligibility.md))).
- 회원 탈퇴(FR-028) 시 회원 정보와 작성한 후기·댓글 처리(삭제 / 익명 유지 / 보관 기간) (출처: 2026-10-29).
