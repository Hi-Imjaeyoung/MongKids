# 요구사항 — 근태 관리 (직원용)

몽키즈 직원 근태 관리 GPS 웹 서비스의 요구사항 단일 출처다.
홈페이지 요구사항은 [requirement_homepage.md](requirement_homepage.md)에 있다.

> **작성 방식**: 회의록(`docs/meetings/`)을 바탕으로 `/extract-requirements`를 실행해 갱신한다.
> 초안을 확인·승인한 뒤 반영하며, 각 항목의 `출처`에 근거 회의록을 적는다.
> 구현·설계 작업은 회의록이 아니라 이 문서를 기준으로 한다.

## ID 규칙

홈페이지 ID와 겹치지 않도록 모든 ID 앞에 `EMP-`를 붙인다.

| 구분 | 형식 | 예 |
|---|---|---|
| 화면 (프론트엔드) | `EMP-SCR-{3자리 번호}` | `EMP-SCR-001` |
| 기능 (백엔드) | `EMP-FR-{3자리 번호}` | `EMP-FR-001` |
| 비기능 | `EMP-NFR-{3자리 번호}` | `EMP-NFR-001` |

- 번호는 이 문서 안에서 001부터 매긴다. 폐기한 ID는 다시 쓰지 않는다.
- 접두사 없는 `SCR-`·`FR-`·`NFR-`는 홈페이지([requirement_homepage.md](requirement_homepage.md)) ID다.

## 상태

EMP-SCR-001(수업 시작·종료 체크)과 관련 FR은 #61에서 구현했다. 나머지는 기획 단계다. 회의에서 나온 아이디어에 ID를 붙여 정리했으며, 아직 착수·확정되지 않았다(상태 `기획`, 지금 범위에서 다루지 않는 항목은 `보류`, 다른 ID로 대체한 항목은 `폐기`).
착수가 결정되면 미결 사항을 정리하고 상태를 `확정`으로 바꾼다.

## 용어

- **수업 시작**: 기존 "출근". 할당된 수업마다 현재 위치로 기관 도착을 확인한다(EMP-FR-001).
- **수업 종료**: 기존 "퇴근". 수업 사진과 특이사항을 제출하며 위치는 쓰지 않는다(EMP-FR-010). 기존 수업 기록(EMP-SCR-003, EMP-FR-006)을 대신한다.

출처: 사용자 결정(2026-10-29)

## 배경 (현재 문제)

- 직원이 거의 모바일로만 확인한다
- 직원이 해당 위치에 도착했는지 확인할 수 없다
- 직원과 의사소통이 어렵다
- 수업 컴플레인, 수업 스케줄 혼동이 생긴다

출처: 2026-10-29
