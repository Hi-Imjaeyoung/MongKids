# 요구사항

프론트엔드와 백엔드가 공유하는 요구사항의 단일 출처다.
기능·화면에는 ID를 붙이고, 커밋·PR·각 영역 문서에서는 이 ID로 참조한다.

> **작성 방식**: 회의록(`docs/meetings/`)을 바탕으로 `/extract-requirements`를 실행해 갱신한다.
> 초안을 확인·승인한 뒤 반영하며, 각 항목의 `출처`에 근거 회의록을 적는다.
> 구현·설계 작업은 회의록이 아니라 이 문서를 기준으로 한다.

## 개요

방문 유아체육 전문 브랜드 **몽키즈**의 웹 서비스.

## 제약 사항

- MVP 배포 목표일: 2026-11-11 (출처: 2026-10-15, 사용자 확인)
- 인프라: AWS (호스팅·DB) (출처: 2026-10-15)
- CI/CD: GitHub Actions 기반으로 프론트·백 배포 파이프라인 통합 (출처: 2026-10-15)
- 월 운영 예산 상한: 50,000~100,000원 (출처: 2026-10-15)
- 현재 홈 시안의 디자인 톤 유지 (출처: 2026-10-15)

## 범위 외

- MVP 제외 화면: SCR-004 행사 프로그램, SCR-005 1:1 방문체육, SCR-008 고객센터, SCR-011 견적 신청 (출처: 2026-10-15)
- 유아 정보 공유 탭: MVP 이후 단계 (출처: 2026-10-15)

## 미결 사항

- SCR-002~003은 홈 시안에서 추정한 화면으로, 범위·구성은 확정이 필요하다.
- GNB "프로그램"과 카드 "정규 체육수업"이 같은 화면인지 (현재 SCR-003으로 묶어 둠)
- 개인 상담 폼(FR-002)에서 보호자 이름, 지역(동), 아이 성별을 빼도 되는지 (2026-10-08 목록에는 있었음)
- 후기 노출 전 승인 여부와 반려 절차 (작성 권한만 "로그인 회원 누구나"로 확정됨)
- 기관 고객 확인 방식, 직원 승인 방식, 관리자와 직원 역할 구분
- 게시물 댓글·공감에 로그인이 필요한지
- 게시물당 사진 최대 장수, 업로드 용량
- SCR-006의 "행사 프로그램" 탭과 MVP에서 제외된 SCR-004의 관계
- SCR-006 화면명 ("수업 현장" 유지 또는 "게시물·소식" 등으로 변경)
- 강사 지원(FR-007)에 로그인이 필요한지, 허용 파일 형식, 알림 메일 수신처
- 비로그인 열람 제한(FR-012)의 "4개"가 게시물·후기 각각인지 합산인지
- 바나나 만족도(FR-016)의 단계 수
- 자동 배포 조건 (배포 브랜치, 수동 승인 여부)
- 아이 건강·알레르기 등 민감 정보 수집 시 개인정보 수집 동의 방식 (회의록에 없음, 검토 제안)
