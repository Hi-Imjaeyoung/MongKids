# ADR-007: 기관 위치 등록에 쓸 지도 API 제공자

- **상태:** Accepted
- **날짜:** 2026-10-29
- **결정 책임자:** Hi-Imjaeyoung
- **관련 항목:** EMP-FR-012, EMP-FR-001, EMP-SCR-006, [ADR-006](ADR-006-attendance-location-verification.md)
- **대체 관계:** 없음

## 1. 배경 및 문제

ADR-006에서 직원 출근을 "기관 좌표에서 반경 100m 안인지"로 판정하기로 했고, 기관 좌표는 관리자가 지도 API로 위치를 찾아 직접 등록·저장하기로 했다(EMP-FR-012). 어느 지도 API를 쓸지는 정하지 않았다.

기관 좌표가 틀리면 그 기관의 모든 출근이 거절된다(ADR-006). 원하는 결과는 **관리자가 기관 주소로 위치를 찾고 지도에서 확인한 뒤, 출근 판정에 쓸 만큼 정확한 좌표를 저장할 수 있는 것**이다. 비용은 들지 않거나 아주 적어야 한다. 판단 기준은 **금액**과 **정확도** 두 가지다(사용자 지정).

## 2. 요구사항 및 제약 조건

### 확인된 사실
- 지도 API를 쓰는 곳은 관리자 화면(EMP-SCR-006)의 기관 위치 등록뿐이다. 출근 판정은 서버가 저장된 좌표로 거리를 계산하므로 지도 API를 호출하지 않는다(ADR-006).
- 필요한 기능은 두 가지다: 주소로 좌표 찾기(지오코딩), 지도에 위치를 표시해 관리자가 확인하기.
- 프로젝트는 이미 카카오 로그인(FR-018)을 쓰고 있고, 카카오 개발자 앱에 웹 도메인 `https://mongkiz.com`이 등록되어 있다(`docs/deploy-checklist.md`). 네이버 로그인도 쓰지만, 네이버 지도 API는 로그인과 다른 서비스(네이버 클라우드 플랫폼)에서 제공한다.
- 비밀값은 커밋하지 않는다(루트 `CLAUDE.md`). 새 외부 의존성은 사용자 확인 후 추가한다.
- **카카오맵** (공식 문서, 2026-10-29 확인):
  - 무료 제공량은 일간 지도 Web SDK 300,000건, 주소로 좌표 변환 100,000건이고, 월간은 전체 API 3,000,000건이다.
  - 초과 시 지도 Web SDK 0.1원/건, 주소로 좌표 변환 0.5원/건, 키워드 장소 검색 2원/건이다.
  - 무료 제공량은 개발자 계정 기준 **처음 카카오맵 API를 활성화한 앱에만** 준다(2026-07-21부터). 무료 제공량을 넘기거나 두 번째 앱부터는 비즈월렛 연결과 유료 설정이 필요하다. 무료 제공량을 다 쓰면 429 오류가 난다.
- **네이버 지도** (네이버 클라우드 플랫폼 공식 가이드, 2026-10-29 확인):
  - Web Dynamic Map, Geocoding 등은 **대표 계정**(Maps를 처음 이용한 계정)에만 무료 이용량을 주고, 그 외 계정은 과금된다.
  - 기존 AI NAVER API 경로의 지도 무료 혜택은 2025-07-01에 끝났고, 지금은 "새로운 Maps" 상품으로 바뀌었다.
  - 현재 무료 이용량 수치와 초과 단가는 공식 문서에서 확인하지 못했다.
- **구글 지도** (공식 FAQ):
  - 2025-03-01부터 월 200달러 크레딧이 없어지고 SKU별 월 무료 사용량으로 바뀌었다.
  - Geocoding·Maps JavaScript가 각각 월 10,000건 무료라는 수치는 제3자 자료에서만 확인했다.
  - 원화 요금과 한국 지역 조건은 확인하지 못했다.

### 가정 및 가설
- 가정: 등록할 기관 수가 적다(대표가 직접 관리하는 규모). 기관 하나를 등록하는 데 주소 검색 몇 번과 지도 표시 몇 번이면 된다. 실제 기관 수는 모른다.
- 가설: 위 가정이 맞으면 카카오·네이버·구글 모두 무료 사용량 안에서 쓸 수 있다. 실제 호출 수는 측정하지 않았다.
- 가정: 국내 주소(도로명·지번)는 국내 지도(카카오·네이버)가 해외 지도(구글)보다 정확하게 찾는다. 비교 측정한 적은 없다.
- 가정: 이 프로젝트의 카카오 개발자 계정에서 카카오맵 API를 아직 다른 앱에 활성화하지 않았다. 확인하지 않았다. 이미 다른 앱에서 썼다면 카카오는 처음부터 유료 설정이 필요하다.
- 가설: 지오코딩 결과가 건물 중심이나 대표 지점이라 기관 출입구와 다를 수 있다. 지도에서 핀을 옮겨 보정할 수 있으면 지오코딩 정확도의 영향이 줄어든다.

### 제약 조건 / 비목표
- 직원 화면에 지도를 띄우는 것, 길 찾기, 장소 추천은 범위가 아니다.
- 출근 판정 방식(반경 100m, 거리만 판정)은 ADR-006에서 정했으므로 다시 다루지 않는다.

## 3. 결정 요인

- **금액 (핵심):** 예상 사용량에서 무료이거나 비용이 아주 적어야 한다. 결제 수단 등록, 계정 조건(첫 앱·대표 계정)처럼 무료 조건을 깨뜨릴 수 있는 요소도 포함한다.
- **정확도 (핵심):** 국내 주소로 찾은 좌표가 실제 기관 위치와 가까워야 한다. 판정 반경이 100m이므로, 지오코딩 오차와 핀 보정 가능 여부가 중요하다.
- **기존 연동 재사용 (선호):** 이미 있는 개발자 계정·도메인 등록을 쓸 수 있으면 설정이 줄어든다.
- **키 관리 (절대 제약):** 서버에서 쓰는 비밀 키는 커밋하지 않는다. 브라우저에 노출되는 키는 도메인 제한이 가능해야 한다.

## 4. 검토한 대안

### 대안 A — 지도 API 없이 좌표 직접 입력 (현상 유지 기준선)
- **접근 방식:** 관리자가 외부 지도 사이트에서 좌표를 복사해 입력한다.
- **장점:** 비용·외부 의존성이 없다.
- **비용 및 위험:** 입력 실수로 좌표가 틀리기 쉽고, 저장 전에 지도로 확인할 수 없다. "지도 API로 등록"하는 EMP-FR-012를 바꿔야 한다.
- **적합한 경우:** 기관이 아주 적고 지도 API 도입을 미룰 때.

### 대안 B — 카카오맵 (지도 Web SDK + 주소로 좌표 변환)
- **접근 방식:** 관리자 화면에 카카오 지도 Web SDK를 띄우고, 주소로 좌표를 찾아 핀을 표시한다. 관리자가 핀 위치를 확인하거나 옮긴 뒤 저장한다.
- **장점:**
  - 무료 제공량과 초과 단가가 공식 문서로 확인된다.
  - 이미 있는 카카오 개발자 계정과 등록된 웹 도메인을 쓸 수 있다.
  - 국내 주소 검색(가정).
- **비용 및 위험:**
  - 무료 제공량은 계정의 첫 카카오맵 활성화 앱에만 준다(활성화 이력 확인 필요).
  - 무료 정책은 바뀔 수 있다고 명시되어 있다(2026-07에 한 번 바뀜).
- **적합한 경우:** 카카오 개발자 계정에 카카오맵 활성화 이력이 없을 때.

### 대안 C — 네이버 지도 (네이버 클라우드 플랫폼 새로운 Maps)
- **접근 방식:** 네이버 클라우드 플랫폼의 Dynamic Map과 Geocoding으로 B와 같은 흐름을 만든다.
- **장점:** 국내 지도(가정). 대표 계정이면 무료 이용량이 있다.
- **비용 및 위험:**
  - 네이버 로그인과 별개인 네이버 클라우드 플랫폼 계정·결제 설정이 새로 필요하다.
  - 현재 무료 이용량 수치를 공식 문서로 확인하지 못했다.
  - 대표 계정이 아니면 과금된다.
  - 무료 정책이 최근 바뀌었다(2025-07).
- **적합한 경우:** 카카오 무료 조건을 쓸 수 없고, 네이버 클라우드 플랫폼 계정을 새로 둘 수 있을 때.

### 대안 D — 구글 지도 (Maps JavaScript + Geocoding)
- **접근 방식:** B와 같은 흐름을 구글 지도로 만든다.
- **장점:** 문서·예제가 많다. SKU별 월 무료 사용량이 있다.
- **비용 및 위험:**
  - 결제 계정 등록이 필요하다.
  - 무료 수치는 제3자 자료로만 확인했다.
  - 국내 주소 정확도가 국내 지도보다 낮을 수 있다(가정).
- **적합한 경우:** 해외 주소를 다뤄야 할 때. 지금은 해당하지 않는다.

### 대안 E — 공공 API (도로명주소 좌표 제공 / 브이월드)
- **접근 방식:** 행정안전부 도로명주소 API나 국토교통부 브이월드로 주소를 좌표로 바꾸고, 지도 표시는 브이월드 지도로 한다.
- **장점:** 공공 서비스라 비용 부담이 낮을 수 있다(확인 필요). 공식 주소 체계를 쓴다.
- **비용 및 위험:**
  - 이용 한도·이용 조건·좌표 기준점을 확인하지 못했다.
  - 좌표계 변환이 필요할 수 있다(확인 필요).
  - 지도 화면 구성이 상용 SDK보다 손이 더 갈 수 있다(가정).
- **적합한 경우:** 상용 API의 무료 조건을 쓸 수 없을 때.

### 대안 비교 요약

| 결정 요인 | A 직접 입력 | B 카카오 | C 네이버 | D 구글 | E 공공 |
|---|---|---|---|---|---|
| 금액 | 없음 | 무료 제공량·단가 공식 확인. 첫 앱 조건 | 대표 계정 무료, 수치 미확인 | 월 무료 사용량(제3자 수치), 결제 계정 필요 | 낮을 수 있음, 미확인 |
| 정확도 | 입력 실수 위험, 지도 확인 없음 | 국내 지도(가정), 핀 보정 가능 | 국내 지도(가정), 핀 보정 가능 | 국내 정확도 낮을 수 있음(가정) | 공식 주소 기반, 기준점 미확인 |
| 기존 연동 | - | 카카오 개발자 계정·도메인 재사용 | 새 계정 | 새 계정 | 새 키 발급 |
| 근거 수준 | - | 공식 문서 | 일부 공식 | 대부분 제3자 | 미확인 |

## 5. 결정

- **선택한 대안:** 대안 B — 카카오맵 (지도 Web SDK + `services` 라이브러리의 주소로 좌표 변환)
- **근거:** 무료 제공량과 초과 단가를 공식 문서로 확인할 수 있고, 예상 사용량(관리자가 기관을 가끔 등록)이 무료 제공량보다 훨씬 적다(가설). 이미 있는 카카오 개발자 계정과 등록된 웹 도메인을 다시 쓸 수 있다. 주소로 찾은 위치를 지도에서 핀을 끌어 보정할 수 있어, 지오코딩이 건물 중심을 돌려줘도 관리자가 출입구 쪽으로 맞출 수 있다.
- **다른 대안을 선택하지 않은 이유:** A(직접 입력)는 저장 전에 지도로 확인할 수 없어 좌표 실수 위험이 크다. C(네이버)는 네이버 클라우드 플랫폼 계정·결제 설정을 새로 만들어야 하고 무료 이용량 수치를 확인하지 못했다. D(구글)는 결제 계정이 필요하고 국내 주소 정확도가 낮을 수 있다(가정). E(공공 API)는 이용 조건·좌표계를 확인하지 못했고 지도 화면 구성이 더 번거롭다(가정).

## 6. 결과

### 기대 효과
- 관리자가 주소로 기관 위치를 찾고, 지도에서 핀과 반경 100m를 보며 출입구 쪽으로 맞춘 뒤 저장한다. 시드 SQL 없이 기관을 등록할 수 있다.
- 서버는 지도 API를 부르지 않는다. 브라우저 키만 쓰므로 서버 비밀값이 늘지 않는다.

### 감수하는 트레이드오프 / 위험
- 무료 제공량은 계정에서 카카오맵을 처음 활성화한 앱에만 준다. 이 조건을 확인하지 못하면 처음부터 유료 설정이 필요할 수 있다.
- 카카오 무료 정책이 다시 바뀌면 비용이 생길 수 있다(2026-07에 한 번 바뀜).
- JavaScript 키는 브라우저에 그대로 보인다. 도메인 제한으로만 막는다.

### 후속 작업
- 어느 대안이든: 지도 API를 관리자 화면에서만 불러온다. 비밀 키는 환경 변수로만 두고 커밋하지 않는다. 브라우저 키는 `mongkiz.com`과 로컬 개발 도메인으로 제한한다.
- 카카오 개발자 콘솔에서 카카오맵 활성화(첫 앱 무료 조건 확인)와 JavaScript 키 도메인(`https://mongkiz.com`, 로컬 개발 주소) 등록. 결정 책임자가 직접 한다.
- 프론트는 SDK를 기관 위치 화면에서만 동적으로 불러온다. 키는 빌드 환경 변수 `VITE_KAKAO_MAP_KEY`(`.env.local`, 커밋 안 함).
- `requirement_employee.md`의 미결 사항 "지도 API 제공자"를 정리하고 EMP-FR-012에 연결했다. (완료, 2026-10-30)

## 7. 검증 계획

- **금액:** 카카오 개발자 콘솔에서 이 계정의 카카오맵 활성화 이력과 "카카오맵 무료 쿼터" 뱃지 여부를 확인한다. 네이버 클라우드 플랫폼 콘솔에서 새로운 Maps 무료 이용량과 대표 계정 조건을 확인한다.
- **정확도:** 실제 기관 주소 3~5곳을 후보 API(B, C, 필요하면 E)로 좌표 변환해, 관리자가 아는 실제 출입구 위치와의 거리를 비교한다. 100m 판정 반경에 비해 오차가 큰지 본다.
- **핀 보정:** 후보 SDK에서 핀을 끌어 위치를 옮기고 그 좌표를 얻을 수 있는지 시험 화면으로 확인한다.
