# ADR-001: ADR 템플릿을 단일 원본으로 관리

> 이 문서는 작성 예시입니다. 이 저장소에서 실제로 내린 결정을 템플릿에 맞춰 기록했습니다. 프로젝트에 설치할 때 `docs/adr/`로 복사하지 마세요.

- **상태:** Accepted
- **날짜:** 2026-10-20
- **결정 책임자:** 저장소 관리자
- **관련 항목:** 커밋 `583174a`
- **대체 관계:** 없음

## 1. 배경 및 문제

ADR 템플릿이 두 곳에 따로 있었고, 두 파일의 내용이 이미 서로 달라져 있었습니다. 사람이 직접 ADR을 쓸 때와 `/adr` 스킬이 ADR을 만들 때 서로 다른 구조의 문서가 생길 수 있습니다. 원하는 결과는 어떤 경로로 만들든 ADR이 같은 구조를 갖는 것입니다.

## 2. 요구사항 및 제약 조건

### 확인된 사실
- `.claude/skills/adr/SKILL.md`는 `references/adr-template.md`를 템플릿으로 사용하도록 지시한다.
- `docs/adr/000-template.md`에는 정식 템플릿에 있는 `관련 항목`, `제약 조건 / 비목표`, `적합한 경우`, `이력` 항목이 없었다.
- `docs/adr/README.md`는 정식 템플릿이 `.claude/skills/adr/references/adr-template.md`에 있다고 안내했다.
- ADR 파일 이름 규칙은 `ADR-NNN-*.md`인데, `000-template.md`는 이 규칙에 맞지 않았다.

### 가정 및 가설
- 가정: 이 템플릿을 쓰는 사용자는 대부분 `/adr` 스킬로 ADR을 만든다. 직접 작성하는 비율은 확인하지 않았다.
- 가설: 템플릿이 하나뿐이면 앞으로 내용이 어긋나는 문제가 생기지 않는다.

### 제약 조건 / 비목표
- 스킬이 읽는 템플릿 경로는 바꾸지 않는다.
- 템플릿 내용 자체를 다시 설계하는 것은 이번 결정의 범위가 아니다.

## 3. 결정 요인

- **변경 용이성:** 템플릿을 고칠 때 수정할 곳이 한 곳이어야 한다. 이 결정의 핵심 요인이다.
- **일관성:** 스킬이 만든 ADR과 직접 쓴 ADR의 구조가 같아야 한다.
- **사용 편의:** 직접 작성하는 사용자도 템플릿을 쉽게 찾을 수 있어야 한다. 선호 사항이다.

## 4. 검토한 대안

### 대안 A — 현상 유지 (두 템플릿 모두 유지)
- **접근 방식:** 두 파일을 그대로 두고, 수정할 때마다 양쪽을 함께 고친다.
- **장점:** 바꿀 것이 없다. `docs/adr/` 안에서 바로 템플릿을 찾을 수 있다.
- **비용 및 위험:** 이미 내용이 달라졌으므로, 사람이 두 곳을 동시에 관리하는 방식은 실제로 지켜지지 않았다.
- **적합한 경우:** 템플릿이 거의 바뀌지 않고, 동기화를 확인하는 자동 검사가 있을 때.

### 대안 B — 스킬 쪽 템플릿만 유지
- **접근 방식:** `docs/adr/000-template.md`를 삭제하고, `docs/adr/README.md`에서 정식 템플릿 위치를 안내한다.
- **장점:** 원본이 하나라 어긋날 수 없다. 스킬 경로를 바꿀 필요가 없다.
- **비용 및 위험:** 직접 작성하는 사용자는 `.claude/` 아래까지 찾아가야 한다.
- **적합한 경우:** ADR을 주로 스킬로 만드는 경우.

### 대안 C — `docs/adr/` 쪽 템플릿만 유지
- **접근 방식:** 정식 템플릿을 `docs/adr/`로 옮기고, SKILL.md가 그 경로를 읽게 한다.
- **장점:** 사람이 찾기 쉽다.
- **비용 및 위험:** 스킬이 자기 디렉터리 밖의 파일에 의존하게 되어, `.claude/`만 복사하면 스킬이 동작하지 않는다.
- **적합한 경우:** 스킬 없이 ADR을 직접 쓰는 팀.

## 5. 결정

- **선택한 대안:** 대안 B — 스킬 쪽 템플릿만 유지.
- **근거:** 핵심 요인인 변경 용이성과 일관성을 가장 단순하게 만족한다. 스킬이 자기 디렉터리 안에서 완결된다.
- **다른 대안을 선택하지 않은 이유:** 대안 A는 이미 관리에 실패한 방식이다. 대안 C는 스킬이 외부 파일에 의존하게 만든다.

## 6. 결과

### 기대 효과
- 템플릿 수정 위치가 한 곳으로 줄어든다.
- `docs/adr/`에는 `ADR-NNN-*.md` 규칙에 맞는 파일만 남아 ID 계산이 단순해진다.

### 감수하는 트레이드오프 / 위험
- 직접 작성하는 사용자가 템플릿을 찾는 데 한 단계가 더 필요하다.

### 후속 작업
- `README.md`의 권장 저장소 구조에서 `000-template.md`를 제거한다. (완료)

## 7. 검증 계획

- `/adr make <topic>`으로 만든 ADR의 섹션 구성이 `references/adr-template.md`와 같은지 확인한다.
- `/adr list` 결과에 템플릿 파일이 나타나지 않는지 확인한다.

## 8. 재검토 조건

- 직접 작성하는 사용자에게서 템플릿을 찾기 어렵다는 피드백이 반복될 때.
- 템플릿 동기화를 자동으로 검사하는 도구를 도입할 때.
